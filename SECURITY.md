# Security

## Reporting a vulnerability

Please do not open a public issue. Email the maintainer (see the GitHub profile) or use
GitHub's private vulnerability reporting. You will get a reply within 72 hours.

## Threat model

apigent sits between an LLM and your API. It assumes the LLM is **untrusted**: it can be
manipulated by the user's prompt or by data returned from tools.

| Threat | Mitigation |
| --- | --- |
| User sees data beyond their rights | Every API call uses the end user's token; the API enforces access. Do not configure a service account. |
| Prompt injection asks for a forbidden tool | `Policy` removes tools before the LLM sees them; a hidden tool returns "does not exist". |
| Indirect injection inside tool results | System prompt marks tool output as data; results are JSON-encoded, never executed. |
| Unwanted writes | Only GET operations are generated by default. |
| PII sent to a third-party LLM | `Transform.mask_fields` / `drop_fields`; or use a self-hosted model. |
| Runaway cost / loops | `max_turns`, `max_tool_calls`, HTTP timeouts. |
| Code execution via math | `calculate` uses an AST whitelist, never `eval`. |

## Recommendations for deployers

- Log tool calls (`on_event` hook) for audit, but never log tokens.
- Run the eval suite with low-privilege tokens to check that refusals hold.
- Rate-limit `/chat` per user.
